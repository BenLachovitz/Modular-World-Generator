# Supabase Backend

This folder contains the Supabase backend used by the Modular World Generator licensing system.

The backend is implemented with Supabase Edge Functions and a PostgreSQL table for storing license keys.

## Components

```txt
Supabase/
├── functions/
│   ├── validate-license/
│   │   └── index.ts
│   └── key-management/
│       └── index.ts
├── sql/
│   └── license_keys_schema.sql
└── README.md
```

## Edge Functions

### validate-license

Client-facing function called by the Unity Editor tool.

Responsibilities:

- Validate license keys
- Activate unused license keys
- Synchronize an existing license for the same user
- Reactivate a previously deactivated license
- Deactivate a license
- Return unlocked Pro features when validation succeeds

Example request:

```json
{
  "action": "activate",
  "licenseKey": "XXXX-XXXX-XXXX-XXXX",
  "userInfo": "local-user-identifier"
}
```

Example successful response:

```json
{
  "valid": true,
  "message": "License activated successfully",
  "features": [
    "pro_tools",
    "advanced_generation"
  ]
}
```

### key-management

Admin-only function called by the Python License Admin Tool.

Responsibilities:

- Generate license keys manually
- Automatically generate keys when the available key pool is low
- Return license statistics
- Insert new license keys into the database

Example request:

```json
{
  "action": "get_stats",
  "adminKey": "your-admin-secret"
}
```

Example response:

```json
{
  "success": true,
  "stats": {
    "total_keys": 10,
    "available_keys": 5,
    "active_licenses": 3,
    "inactive_licenses": 2
  }
}
```

## Required Database Table

The backend expects a table named:

```txt
license_keys
```

Recommended schema:

```sql
create table if not exists public.license_keys (
    id bigint generated by default as identity primary key,
    key text not null unique,
    is_active boolean not null default false,
    user_info text,
    activated_at timestamptz,
    created_at timestamptz not null default now()
);

create index if not exists idx_license_keys_key
on public.license_keys(key);

create index if not exists idx_license_keys_user_info
on public.license_keys(user_info);

create index if not exists idx_license_keys_available
on public.license_keys(user_info)
where user_info is null;
```

## Required Supabase Secrets

The Edge Functions use Supabase environment variables/secrets.

Required:

```txt
ADMIN_SECRET
SUPABASE_SECRET_KEYS
SUPABASE_PUBLISHABLE_KEYS
SUPABASE_URL
```

In newer Supabase projects, `SUPABASE_SECRET_KEYS` and `SUPABASE_PUBLISHABLE_KEYS` may be available automatically as JSON objects.

The functions parse the `default` key from these objects.

Example conceptual structure:

```json
{
  "default": "sb_secret_or_publishable_key"
}
```

## JWT Verification

For this project, JWT verification should be disabled for both Edge Functions:

```txt
validate-license
key-management
```

Reason:

The Unity tool and Python admin tool are not using Supabase Auth user JWTs.

Authorization is handled inside the functions:

- `key-management` uses `ADMIN_SECRET`
- `validate-license` validates the submitted license key and user identifier

## Security Notes

The Supabase secret key must never be placed inside:

```txt
Unity project
Python admin tool
README files
GitHub repository
Screenshots
Client-side code
```

The secret key is used only inside Supabase Edge Functions to communicate with the database.

The Unity tool and Python tool should only use the Supabase publishable key.

## Proof-of-Concept Note

This licensing system was created as part of an academic final project.

It demonstrates a practical Pro-license workflow using Supabase Edge Functions, but it should be reviewed and hardened further before being used as a real commercial DRM or payment-based licensing system.
